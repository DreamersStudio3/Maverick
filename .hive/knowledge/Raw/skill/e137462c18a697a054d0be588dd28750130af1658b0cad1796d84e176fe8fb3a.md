# 개발자 문답형 위키 초안

## 목표

코드에서 확인 가능한 사실과 개발자만 아는 의도를 분리. 질문 최소화. 최종 결과는 개발자가 Obsidian에서 바로 확장할 수 있는 `docs/wiki/` Markdown 문서.

## 1. 변경 근거 확인

- 관련 TODO, 변경 diff, 검증 결과 확인
- 구조·책임·관계 변화: Graphify 우선 조회 후 원본 확인
- 코드·에셋에서 확인된 사실과 개발자 의도 분리
- 장기 지식 변화 없음: `변경 불필요: <구체적 이유>` 반환 후 종료

## 2. 변경 후보 확인

확인된 변경을 최대 5개 체크 항목으로 제시. 한 번에 질문 하나만 제시하고 응답 대기.

```text
확인한 변경 후보
1. <변경>
2. <변경>

위 목록이 실제 변경과 맞나요?

- 전부 맞으면: "맞아"
- 내용이 다르면: "2번은 <실제 내용>이야"
- 빼고 싶으면: "3번은 빼줘"
```

사용자가 이해할 수 있는 일상어만 사용. `틀린 항목`, `제외 항목`, `이상 없음`처럼 응답 형식을 해석해야 하는 축약 안내 금지. 후보 단계에서 구현 이유나 설계 의도 추측 금지.

## 3. 개발자 의도 질문

코드와 기존 대화에서 답을 찾을 수 없는 항목만 질문. 항목별 한 질문, 전체 최대 3개.

우선순위:

1. 이번 작업의 핵심
2. 기존 방식의 문제 또는 변경 이유
3. 이후에도 지킬 기준이나 남은 제약

답변에 이미 포함된 질문 생략. 장문 답변 요구 금지. 키워드·한 문장 답변 허용.

## 4. 압축 초안 반환

다음 제목 중 내용이 있는 것만 사용.

```markdown
## 핵심
- <한 줄>

## 변경
- <한 줄>

## 기준
- <한 줄>

## 남은 일
- <한 줄>
```

출력 제한:

- 전체 최대 8개 bullet
- bullet당 한 문장, 권장 60자 이하
- 식별자·경로·명령어의 정확한 표기 유지
- 개발자 표현의 의미만 압축, 문체 미화 금지
- 서론·결론·효과 홍보·일반론 금지
- 근거 없는 설계 의도·장점·미래 계획 금지
- 미확정 내용: `확인 필요: <항목>`

압축 초안을 채팅으로 먼저 반환. 파일명 승인 전 `docs/wiki/` 편집 금지.

## 5. 파일명 제안과 문서 생성

압축 초안 반환 후 다음 순서 사용:

1. `docs/wiki/`의 기존 파일명과 같은 주제 문서 확인
2. 영어 단어와 숫자, 하이픈만 사용한 `Pascal-Kebab-Case.md` 파일명 하나 제안
3. 제안 이유를 한 줄로 설명하고 생성 여부 질문
4. 사용자 승인 또는 사용자가 지정한 영문명 수신까지 대기
5. 대상 파일 부재 확인 후 `docs/wiki/<승인명>.md` 생성

```text
제안 파일명: docs/wiki/Internal-Wiki-Pipeline.md
이 이름으로 만들까요? 괜찮으면 "좋아", 바꾸려면 원하는 영어 파일명을 알려주세요.
```

생성 규칙:

- 첫 줄: 내용을 나타내는 한국어 H1 제목
- 본문: 직전에 확정한 압축 초안
- 승인받지 않은 이름 사용 금지
- 기존 파일 자동 덮어쓰기 금지
- 이름 충돌 시 기존 문서 갱신 또는 다른 파일명 중 사용자 선택 요청
- 파일 생성 후 생성 경로와 Obsidian 열기 결과만 간단히 안내

## 6. Obsidian 열기

문서 생성 성공 직후 사용자가 열기 제외를 요청하지 않았다면 다음 순서 사용:

1. 생성한 Markdown의 절대 경로 확인
2. 경로 구분자를 `/`로 정규화한 뒤 절대 경로 전체를 URI 값으로 백분율 인코딩
3. 생성 경로를 포함하는 Obsidian 보관함 등록 여부를 확인할 수 있으면 확인
4. 보관함 등록 확인 시 `obsidian://open?path=<인코딩한 절대 경로>&paneType=tab`을 호스트의 보이는 URI 실행 방식으로 열기
5. 보관함 미등록 확인 시 `obsidian://choose-vault`로 Obsidian 보관함 선택 화면 열기

열기 규칙:

- 이미 생성한 파일에 `obsidian://new` 사용 금지
- 앱 창을 숨기거나 백그라운드 전용으로 실행 금지
- URI 실행 성공은 운영체제에 열기 요청이 전달된 범위만 증명. 문서 탭 활성화까지 검증하지 못하면 `Obsidian 문서 열기 요청 완료`로 안내
- 보관함 미등록 시 `Obsidian 실행 완료, 프로젝트 폴더의 보관함 등록 필요`로 안내
- URI 처리기 또는 데스크톱 앱 실행 불가 시 문서 생성 유지. `Obsidian 열기 실패: <정확한 이유>`와 생성 경로 안내
- 현재 호스트에 데스크톱 앱 실행 기능이 없으면 열기 건너뜀. 현재 호스트와 건너뛴 이유 안내

## 7. 인계

- 개발자: 생성된 Markdown 문서를 Obsidian에서 확장·수정
- 편집 완료 전달 이후: 프로젝트의 기존 위키 커밋·push 절차 사용
- 초안과 최종 위키의 문장 비교·승인 상태·내용 해시 검사 금지
