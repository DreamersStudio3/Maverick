# 보스 처치 아이템 직접 지급

설계안 · 2026-11-25 · 싱글플레이

보스가 죽는 순간 보상 아이템이 플레이어 가방에 들어간다. 바닥 구체나 E 입력 없이 기존 하단 습득 카드와 오른쪽 목록이 함께 뜬다. 첫 적용 대상은 `TestMap`의 훈련용 `BP_Carcass3`, 예시 보상은 철 파편 4개다

## 첫 적용 위치

| 항목 | 현재 | 적용안 |
|---|---|---|
| 대상 | `BP_Carcass` 클래스의 배치 개체 `BP_Carcass3`. 생성 지점은 `FieldSpawn_TestMap_Carcass`, 지점 ID는 `TestMap.CarcassTraining` | 이 지점에서 관리하는 개체와 휴식 후 다시 생성된 개체에 적용 |
| 보상 | `DT_EnemyDrops.TestMap_Carcass`에서 `Item.Material.IronShard` 1개를 바닥에 생성 | 같은 표의 직접 지급 행 `Boss_Carcass_Trial`에서 철 파편 4개를 지정 |
| 플레이 결과 | 구체에 다가가 E를 누르면 철 파편이 들어옴 | 사망 즉시 가방 +4, 하단 카드 4장, 오른쪽 4줄. 양쪽에 각각 3개가 먼저 뜨고 네 번째는 빈자리가 생기면 표시. 해당 사망에서 생성한 구체 0개 |

같은 외형을 시험용 일반 적과 보스 양쪽에 쓸 수 있다. 보상은 배치 지점이 선택한 표의 행으로 결정한다. 기존 배치와 드롭의 근거는 [필드 아이템 설계](item-drop-pickup.md)와 [휴식 거점의 TestMap 배치 기록](../wiki/Features/Rest-Point/document.md)에 있다

## 보상표와 사망 처리

- 기존 `FMVEnemyDropTableRow`에 전달 방식 `WorldPickup`(바닥에 생성), `DirectToInventory`(가방에 지급)를 제안한다. 기존 행의 기본값은 `WorldPickup`. 두 방식 모두 같은 `GuaranteedDrops` 목록의 아이템 태그·수량·작성 순서를 사용한다. 구체 클래스 `PickupClass`는 바닥 방식에서만 필요하다. [현재 보상 행](../../Source/Maverick/Public/Tables/MVEnemyDropTableTypes.h)
- 사망을 받는 곳은 기존 `AMVFieldEnemySpawnPoint` 한 곳이다. 서버 권한에서 현재 추적 중인 적의 `OnDeathStarted`를 생명당 한 번만 처리한다. 전달 방식을 먼저 고르고, 바닥 방식에서만 지면 검사와 구체 생성을 실행한다. 휴식으로 적을 교체하거나 레벨을 떠나면서 액터를 제거할 때는 보상이 없다. [현재 적 생성 지점](../../Source/Maverick/System/MVFieldEnemySpawnPoint.cpp)
- 정식 보스에는 배치된 보스를 **보상만 관찰**하는 지점을 연결한다. 이 지점은 최초 보스의 사망 구독과 해제를 맡는다. 등장 연출에 연결하면 자동으로 관찰 모드가 되고, 연출이 없으면 지점에서 직접 설정한다. 훈련용 지점은 재생성 때 새 생명을 다시 구독한다
- 직접 지급의 수령자는 해당 월드와 저장 슬롯의 로컬 플레이어다. 마지막 공격이 지속 피해이거나 공격자가 이미 사라졌어도 같은 플레이어가 받는다. 공격·회피 중에도 지급하고, 플레이어가 동시에 죽어 가방 복원 중이면 같은 슬롯의 다음 가방이 준비된 뒤 지급한다

## 가방과 알림

1. 보상 행에서 지급할 태그와 수량을 읽는다. 아이템 등록 여부, 양수 수량, 고유 무기 수량 1을 검사한다. 잘못된 행은 맵 검증에서 지점·행·태그와 함께 보고한다
2. 인벤토리의 기존 지급 검사와 수량·최초 발견 갱신을 재사용한다. 가방과 보상 처리 기록을 함께 반영한 뒤 실제로 늘어난 수량으로 `OnItemAcquired`를 보낸다. 저장과 알림까지 실행하는 `TryGrantItem`을 먼저 호출하고 나중에 별도로 완료 표시를 쓰면 두 기록이 어긋날 수 있어, 고정 배치물 습득에서 쓰는 일괄 반영 방식을 재사용한다. [인벤토리 지급 코드](../../Source/Maverick/Components/MVInventoryComponent.cpp) · [월드 저장 코드](../../Source/Maverick/System/MVWorldStateSubsystem.cpp)
3. 하단 카드와 오른쪽 목록은 지금처럼 인벤토리의 습득 신호를 받는다. 철 파편 3개를 한 번에 지급하면 신호 1건, 카드 3장, 오른쪽 3줄이다. 각 위치는 동시에 최대 3개를 표시하고 나머지는 순서대로 표시한다. 무기는 가방에 소유만 추가하고 퀵슬롯 등록은 휴식 거점에서 한다. [습득 알림 설계](item-acquisition-notifications.md)

## 바로 넣을 수 없는 보상과 저장

| 상황 | 처리 제안 |
|---|---|
| 가방에 자리가 있거나 일부만 들어감 | 들어가는 수량만 지급한다. 같은 보상의 다른 품목도 순서대로 검사하고 남은 수량만 현재 슬롯에 보관 |
| 소지 한도에 도달했거나 플레이어 가방이 준비되지 않음 | 바닥에 구체를 만들지 않고 미지급 태그·수량을 보관. 같은 슬롯의 가방 복원 완료 또는 소지 수량 감소 시 자동 재시도 |
| 고유 무기를 이미 소유 | 해당 항목의 보상 조건을 충족한 것으로 처리. 추가 소유·대기·습득 알림은 0건. 함께 든 재료는 정상 지급 |
| 중복 사망 신호·저장 재시도·슬롯 전환 | 한 생명의 사망 처리 키로 중복 접수를 막고, 미지급분은 획득 당시 슬롯에 귀속. 가방 수량·발견 기록과 보상 잔량을 같은 저장본에 반영한 뒤 실제 지급분만 알림 |

미지급 기록에는 이번 처치의 식별값과 표에서 확정한 태그·남은 수량을 담는다. 보스가 사라진 뒤에도 액터 참조나 보상표를 다시 읽을 필요가 없다. 대기분 지급 중 발생한 가방 변경 신호가 같은 대기분을 다시 지급하지 않도록 한 번에 한 건씩 반영한다

저장 파일 쓰기에 실패하면 이번 플레이의 가방과 잔량을 함께 유지하고 다음 저장에서 다시 쓴다. 기록이 없는 기존 저장은 대기 보상 0건으로 시작한다. 이미 받은 아이템을 불러오는 것에는 알림이 없고, 불러온 뒤 대기 보상이 실제로 새로 들어갈 때에는 알림이 뜬다

이번 예시의 지급 횟수는 **한 생명당 한 번**이다. 훈련용 Carcass를 휴식으로 되살려 다시 처치하면 다시 받는다. 정식 보스를 저장 슬롯당 한 번만 처치할 수 있게 하는 규칙은 보스 재등장 정책에서 결정한다. 등장 연출의 관람 기록은 보상 수령 여부를 나타내지 않는다

## 단계별 구현과 완료 기준

| 단계 | 작업 | 확인할 결과 |
|---|---|---|
| 1. 보상표와 사망 연결 | 두 전달 방식, 기존 행 기본값, 보상 전용 관찰, 중복 구독 방지, 철 파편 4개 시험 행 | 일반 적은 기존 구체 1개. 연출 유무에 관계없이 지정한 보스는 사망 1건만 접수. 휴식·레벨 이탈로 제거한 적은 0건 |
| 2. 직접 지급과 예외 처리 | 인벤토리 지급 검사, 미지급 잔량 저장·재시도, 기존 알림 연결 | 4개 지급 시 양쪽 3개 표시 후 네 번째 추가. 한도 때문에 1개만 받으면 양쪽 1개, 나중에 남은 3개를 받으면 양쪽 3개. 중복 무기만 있는 경우 양쪽 0개 |
| 3. TestMap 적용과 검증 | `Boss_Carcass_Trial` 연결. 별도 저장 폴더에서 실제 처치·휴식·재접속 시험 | E 입력 없이 철 파편 +4, 두 위치에서 각각 알림 4개 순차 표시, 바닥 구체 0개. 재처치는 +4, 같은 사망 신호 재호출은 +0. 슬롯 변경·동시 사망·저장 재시도에서 분실·중복 없이 원래 슬롯에만 반영 |

검증에는 보상 없는 같은 클래스 개체, 일반 적의 바닥 드롭, 기존 세 개의 고정 배치물도 대조군으로 둔다. 직접 지급 여부는 눈에 보이는 구체, 가방 수량, 양쪽 알림 수를 함께 확인한다

### 1단계 구현 상태

`DT_EnemyDrops.Boss_Carcass_Trial`에 직접 지급 방식으로 철 파편 4개 등록. 생성 지점의 `Observe Placed Enemy Only` 설정은 대상의 사망만 구독하며 휴식 시 적 교체에서 제외된다. 등장 연출에 연결된 적은 자동으로 이 방식으로 관찰한다

Windows Unreal Editor 5.8.1의 별도 시험 월드에서 저장된 보상 행, 중복 사망·중복 관찰 방지, 일반 행의 구체 생성과 휴식 초기화 확인. 실제 인벤토리 지급은 2단계, TestMap 개체 연결과 플레이 검증은 3단계 범위

### 2단계 구현 상태

적 생성 지점이 직접 지급 행을 보상 처리기에 전달하면 현재 슬롯에 보상 수량을 기록한다. 그 프레임의 사망 처리가 끝난 뒤 로컬 플레이어 가방에 지급하고, 가방과 미지급 잔량을 같은 저장본에 반영한다. [보상 처리기](../../Source/Maverick/System/MVEnemyRewardSubsystem.cpp)

가방 복원, 조종 캐릭터 교체, 필드 전환 종료, 보유 수량 변경 시 남은 보상을 재검사한다. Windows 에디터의 격리된 시험 맵과 두 저장 슬롯으로 사망부터 지급까지 확인했다. TestMap 실전과 동시 사망 후 부활, 저장 쓰기 실패 후 재시도 검증은 3단계 범위다

### 3단계 적용과 검증

`TestMap`의 `FieldSpawn_TestMap_Carcass`에서 `Enemy Drop Row`를 `Boss_Carcass_Trial`로 지정했다. 연결 대상은 `BP_Carcass3`이며, 같은 지점에서 휴식·부활로 되살아난 개체에도 같은 보상을 적용한다

Windows Unreal Editor 5.8.1에서 창을 띄우지 않는 에디터 플레이와 별도 저장 경로로 다음 항목을 확인했다. 적 HP를 0으로 만들어 실제 사망 처리를 실행했으며 에디터에서 전투 조작을 재현하는 시험은 별도 범위다

| 확인 항목 | 결과 |
|---|---|
| 첫 처치와 중복 신호 | 가방 +4, 하단 카드 4장·오른쪽 4줄 순차 표시, 새 구체 0개. 기존 고정 구체 세 개 확인 |
| 휴식·동시 사망 | 휴식 후 새 Carcass 확인. 플레이어와 재생성된 적이 같은 프레임에 사망하면 미지급 4개를 저장하고 부활 뒤 지급해 가방 누계 8개 |
| 쓰기 실패·재시도·재접속 | 시험 슬롯의 쓰기를 차단해도 세 번째 처치 후 가방 누계 12개 유지. 쓰기 재시도와 새 에디터 플레이에서 12개 복원, 새 습득 알림 0건 |

기록은 `Saved/Logs/BossRewardStageThree-FinalPIE.log`의 `Maverick.Inventory.EnemyRewardTestMap`에 있다. TestMap 시작 시 발생하는 기존 StateTree 초기화 오류는 해당 메시지를 특정해 보상 시험의 판정에서 제외했다
