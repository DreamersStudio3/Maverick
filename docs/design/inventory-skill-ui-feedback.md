# 인벤토리 조작과 스킬 선택 화면 개선

2026-11-19 · 구현 전 설계 · Windows / Unreal Engine 5.8

## 1. 인벤토리에서 첫 클릭부터 선택

`I`를 누르면 필드 메뉴에 마우스 포인터가 보이고, 첫 클릭으로 Inventory를 연다. 이어서 분류·아이템·뒤로 가기를 마우스로 선택할 수 있다. 열린 동안에도 세계와 적은 움직인다

- 현재 `UMVInventoryWindow`는 공통 창의 메뉴 입력 설정을 상속한다. 이 설정은 마우스 캡처를 풀도록 요청하며, TestMap의 보스 시험 패널도 매 프레임 커서와 캡처를 제어할 수 있다. 시험 패널에는 활성 창을 확인하는 조건이 있어 실제 실행 순서 확인이 필요하다
- 구현 첫 작업은 TestMap에서 마우스로 시점을 돌리다가 `I`를 누르는 상황 재현. 열기 직전·활성화·다음 프레임·첫 클릭·닫기 시점에 입력을 맡은 창, 장치, 커서 표시, 마우스를 잡고 있는 위젯, 실제 클릭 대상을 임시 로그로 비교
- 필드 메뉴와 인벤토리는 같은 창의 입력 권한을 사용한다. 메뉴가 위에 있는 동안 게임 화면과 시험 패널이 마우스를 다시 잡지 않도록, 추적에서 확인한 경로를 수정한다. 페이지 이동 때마다 커서를 숨기거나 중앙으로 돌리는 처리도 피한다
- 마우스 클릭은 메뉴에서 한 번만 소비한다. 패드로 바꾸면 현재 페이지의 버튼에 초점을 주고, 마우스를 다시 움직이면 바로 가리켜 선택할 수 있게 한다
- 일반 닫기 때는 필드가, 피격·사망·필드 이동으로 닫히면 그 시점의 최상위 화면이 입력을 이어받는다

## 2. Information 아래의 한글 설명

첨부 화면에서 영문 제목 `Information`은 읽히고 아래 본문이 네모로 보인다. `UMVInventoryPage::RefreshDetails`는 아이템 표의 `Description`을 위젯 `ItemDescription`에 전달한다. 플레이어 무기 표에는 ‘테스트 무기’라는 한글이 들어 있고, 인벤토리 페이지 자산은 Liberation Serif와 Optimus Princeps를 참조한다

- 같은 아이템 행의 원문, 실행 중 `ItemDescription`의 문자열, 실제 그려진 글자를 순서대로 대조한다. 잘못 저장된 글자와 글꼴에 글자 모양이 빠진 경우를 이 단계에서 구분한다
- 표시할 문자열이 정상일 때는 인벤토리의 아이템 이름·설명 등 데이터가 들어오는 텍스트에 한글을 지원하는 글꼴을 적용한다. 영문 모양을 유지할 수 있도록 영문은 기존 서체, 한글은 한글 서체로 그리는 조합을 우선한다. 기존 공유 글꼴의 전역 수정보다 해당 위젯의 글꼴 지정을 우선한다
- 에디터와 독립 게임 모두에서 쓸 수 있는 한글 글꼴을 선택한다. 한국어·영문이 섞인 문장, 두 줄 이상 설명, 설명이 비었을 때의 기존 안내 문구로 줄바꿈과 하단 잘림을 확인한다

## 3. 필드 메뉴 ↔ 인벤토리 전환

현재 두 페이지는 `UMVInventoryWindow` 안의 `UWidgetSwitcher`가 즉시 교체한다. 같은 창을 유지한 채 보이는 페이지의 투명도만 바꾼다

| 구간 | 제안 동작 |
|---|---|
| 메뉴에서 Inventory 선택 | 메뉴가 0.08초 동안 사라짐 → 인벤토리 데이터와 페이지 교체 → 인벤토리가 0.10초 동안 나타남 |
| 인벤토리에서 뒤로 | 같은 속도로 반대로 전환. 메뉴의 Inventory 버튼으로 초점 복귀 |
| 전환 중 클릭·확인·뒤로 연타 | 최초 페이지 전환 한 건만 처리. 숨은 버튼과 뒤쪽 전투 화면은 클릭을 받지 않음 |
| 어느 시점이든 `I` 또는 피격·사망·필드 이동 | 페이지 연출을 취소하고 창을 닫음. 다음 프레임에 사라진 페이지가 다시 열리거나 초점을 가져가지 않게 처리 |

기존 `FMVUIFadeController`를 페이지 전환에 재사용한다. 화면 전체나 전투 HUD까지 어두워지지 않게 페이지에 적용한다. 페이지가 교체되는 시점에 소지품 연결을 붙이거나 해제하고, 전환 완료 시 선택할 아이템 또는 분류 버튼에 초점을 둔다

처음 `I`로 창을 여는 공통 연출과 페이지 연출이 겹치더라도 첫 클릭은 받는다. 창을 다시 열 때는 첫 페이지와 정상 투명도에서 시작한다. 왕복 한 방향 **0.18초**는 플레이 감각을 확인할 초기값

## 4. 장착 스킬을 후보 첫 줄에 표시

현재 `UMVWeaponSkillSelectionWindow::RebuildCandidates`는 장착 후보를 찾아 미리보기에 표시하지만 행은 받은 순서대로 화면에 추가한다. 이 때문에 Q를 열면 ‘장착 중’이 선택된 채 두 번째 줄에 보일 수 있다

- 현재 보고 있는 무기와 슬롯에서 이미 적용한 후보를 첫 줄에 놓는다. 나머지는 기존 상대 순서를 유지한다. Q·W·E·R과 패시브에 같은 규칙을 적용하고, 패시브의 ‘선택 해제’는 마지막에 둔다
- 선택한 항목이 없는 슬롯은 기존 첫 후보부터 표시한다. 다른 무기 스타일에 저장한 선택이나 미완성 기술에는 기존 ‘선택됨’·‘준비 중’ 표시 규칙을 적용한다
- 처음 열거나 탭을 바꾸면 첫 줄과 미리보기가 맞아야 한다. 다른 후보를 클릭하거나 방향키로 둘러볼 때는 목록을 고정하고, **적용이 성공한 순간** 새 장착 항목을 첫 줄로 옮겨 초점과 스크롤을 맞춘다
- 정렬은 화면에 표시할 후보 사본에서 수행한다. 실제 장착 판정, 잠금 비용, 기본 스킬 결정, 저장 식별자는 기존 무기 시스템이 계속 담당한다

## 5. 기존 Q·R 아이콘 복구

이전 전투 HUD가 사용한 자산은 `/Game/UI/Textures/Skills/Yone/`에 있다. 현재 후보 행과 탭은 스킬 표의 `Icon`을 읽고, 미리보기는 `PreviewImage`가 비면 `Icon`을 사용한다. 전투 HUD도 장착 행과 이어지는 연계 행의 `Icon`을 읽는다

| 대상 | 스킬 표에 연결할 기존 그림 | 플레이어가 보는 결과 |
|---|---|---|
| 기존 Q 시작·2단계·3단계 | `T_Icon_Yone_SkillQ_1`, `T_Icon_Yone_SkillQ_2`, `T_Icon_Yone_SkillQ_3` | 선택 화면은 시작 그림, 전투 HUD는 진행 단계에 맞는 그림 |
| 기존 R | `T_Icon_Yone_SkillR` | 해당 기술의 후보·탭·미리보기와 전투 HUD에 동일한 기술 표시 |

- 한손 시험 무기 `Test_OneHand`의 Q에는 `Yone_Attack`의 `SkillQ`와 `LightAttack2`가 함께 등록되고, R 후보에는 `SkillE`가 등록된 기록이 있다. 표 안에는 `SkillR`라는 이름도 있다
- 편집 전 실제 장착 행의 **표 경로와 행 이름**, Q의 다음 행 연결, R 실행에 연결된 기술을 에디터에서 확인한다. 원래 Q 연계와 R에 해당하는 행에만 그림을 넣는다. 이름이 비슷한 행이나 같은 키에 넣을 수 있는 다른 후보에 일괄 적용하지 않는다
- 출력 크기는 기존 후보·미리보기·전투 HUD 규칙을 따른다. 전용 미리보기가 있으면 유지하고, 그림이 없는 다른 후보는 공통 그림을 사용한다

## 구현 순서와 통과 기준

| 순서 | 실행 환경과 확인 기준 |
|---|---|
| 1. 커서 복구 | Windows TestMap 에디터 플레이와 독립 게임에서 시점 조작 → `I` → 추가 조작 없이 Inventory 첫 클릭 → 분류·아이템·뒤로 선택. 실제 포인터 표시와 클릭 도착을 모두 확인. 메뉴에서 공격이 나가지 않고 닫은 뒤 시점·공격 복구 |
| 2. 설명 표시 | 같은 무기의 표 원문과 화면 글자 대조. ‘테스트 무기’, 한영 혼합, 긴 설명, 빈 설명을 작은 창과 일반 해상도에서 확인 |
| 3. 양방향 전환 | 왕복과 빠른 연타, 사라지는 도중·나타나는 도중 피격, 재개방을 각각 확인. 게임 시간 진행, 한 번의 페이지 변경, 올바른 초점과 커서 복귀 |
| 4. 스킬 정렬과 아이콘 | 실제 한손 무기의 Q·R을 열어 첫 줄·선택 강조·미리보기·전투 그림 대조. 후보 열람, 다른 후보 적용, 탭 재진입과 저장 후 재진입, Q 3단계·R 게이지 표시, 다른 후보의 공통 그림 확인 |

현재 근거는 첨부 화면, Windows 작업 사본의 소스·자산 참조와 이전 HUD 코드다. 위 표는 구현 후 시행할 검사다. 특히 커서가 사라지는 프레임과 본문에 실제 선택된 글꼴은 실행 중 확인할 항목이다
