# 문서와 Graphify 운영 워크플로

## 목적

Maverick 지식 운영 원칙: 사람이 검토하는 위키와 에이전트의 로컬 코드 탐색 캐시 분리.

## 정보 계층

| 위치 | 역할 | Git 정책 |
| --- | --- | --- |
| `docs/todo/<task>.md` | 진행 상태, 결정, 검증, 위키 검토 | 작업 중 추적, 완료 후 삭제 |
| C++ 헤더 `/** ... */` | 타입 인접 책임·수명·불변조건 | 코드와 함께 추적 |
| `docs/wiki/Architecture.md` | 구조·책임 경계·주요 흐름·에셋 공백 | 에이전트 초안과 사람 편집 후 추적 |
| `docs/wiki/` | 설계 의도와 장기 운영 지식 | 에이전트 초안과 사람 편집 후 추적 |
| `graphify-out/` | 에이전트용 로컬 코드 그래프 | 전체 무시, 공유 금지 |
| `.agent-tools/` | 프로젝트 고정 Graphify 실행 환경 | 전체 무시, 공유 금지 |

## Agent 의존성

버전 기준: `Config/AgentDependencies.json`.

첫 material 작업과 원격 push 직전 실행:

```powershell
./Scripts/Agent/Ensure-AgentDependencies.ps1 -HostName codex
```

호스트 선택값: `codex`, `claude`, `antigravity`.

스크립트 책임:

- Aigent Hive 고정 버전 확인과 공식 npm 패키지 자동 설치
- Hive 사용자 설치 검증과 필요 시 서명 CLI 적용
- 프로젝트 Hive harness 존재 확인
- 프로젝트 로컬 Python 가상환경의 Graphify 고정 버전 설치
- 사용자 범위 Graphify agent skill 설치

설치 또는 검증 실패 시 material 작업·push 중단.

## Query-driven Graphify

### 적용 대상

- 여러 파일을 가로지르는 구조·책임·호출 흐름 질문
- 심볼 간 연결 경로 조사
- 대규모 수정 전 영향 범위 조사
- 기존 위키와 현재 코드의 불일치 확인

단일 파일·명확한 심볼·단순 문구 수정: Graphify 생략 가능.

### 질의 흐름

1. `POLICY.md`, 관련 TODO, `docs/wiki/Architecture.md` 확인
2. Graphify wrapper 실행
3. wrapper의 로컬 그래프 초기화 또는 코드 AST 증분 갱신
4. 좁혀진 원본 코드 확인
5. Blueprint·StateTree·Chooser·Montage·DataTable·WBP 관련 판단의 Unreal Editor 검증

```powershell
./Scripts/Graphify/Invoke-Graphify.ps1 query "액션 입력에서 전투 실행까지의 흐름"
./Scripts/Graphify/Invoke-Graphify.ps1 path "MVInputManagerComponent" "MVCombatComponent"
./Scripts/Graphify/Invoke-Graphify.ps1 explain "MVActionComponent"
```

초기 그래프: 동일 Git snapshot, `.gitignore`, `.graphifyignore`, Graphify 버전 기준의 code-only AST 추출.

기존 그래프: 질의 직전 `graphify update . --no-cluster` 실행으로 코드 관계 갱신.

문서 의미 추출·커뮤니티 이름·생성 wiki·HTML: 기본 파이프라인 제외. 장기 설명은 `docs/wiki/` 원문 직접 확인.

## 갱신 시점

| 시점 | 행동 |
| --- | --- |
| 일반 프롬프트 | 의존성 확인 후 관련 작업 시작 |
| 코드 구조 질문 | 질의 wrapper를 통한 로컬 Graphify 준비와 조회 |
| 일반 커밋 | Graphify 작업 없음 |
| switch/checkout | Graphify 작업 없음, 다음 관련 질의에서 갱신 |
| 대규모 refactor·추출기 변경 | 다음 질의 전 `graphify-out/` 삭제 후 전체 초기화 고려 |
| 구현·검증 완료 | 에이전트의 위키 영향 분석과 근거 기반 초안 생성·갱신 |
| 사람 편집 완료 전달 | 현재 위키를 최종본으로 취급, 위키 전용 커밋 준비 |
| 원격 push 전 | 의존성 재검증, 위키 전용 커밋, PR 링크, 빌드·테스트 확인 |

금지 항목:

- Graphify post-commit·post-checkout 훅 설치
- `graphify-out/` stage·commit·push
- 생성 graph·wiki·HTML 직접 수정
- Graphify 결과만으로 Unreal binary asset 연결 확정

## 작업 문서와 위키

작업 시작 시 `docs/todo/<task>.md` 작성. 최소 필드: 목표, 상태, 결정, 위키 검토, 검증.

구조·책임·수명·주요 흐름 변경 시 관련 `docs/wiki/` 문서 갱신. `Architecture.md` 대상:

- 모듈·플러그인·디렉터리 책임 변화
- Component·Subsystem 소유권 또는 수명 변화
- 입력·전투·피격·사망·필드 전환·AI·UI·테이블 주요 흐름 변화
- C++와 Blueprint 사이 책임 이동
- 주요 타입 이동·이름 변경·삭제

함수 내부 구현만의 변경: 위키 변경 불필요 사유 기록 가능.

### 초안과 사람 편집

1. 구현과 관련 검증 완료 후 에이전트가 변경 코드·에셋·결정을 근거로 기존 위키 갱신 또는 새 문서 초안 작성
2. 불확실한 에셋 연결·수치·의도는 확정 사실처럼 작성하지 않고 확인 필요 범위 명시
3. 개발자가 `docs/wiki/`를 Obsidian으로 열어 사람의 설명과 프로젝트 지식으로 수정·첨삭
4. 개발자의 편집 완료 전달을 문서 최종화 신호로 사용
5. 승인 상태, 별도 승인자, 초안 대비 차이, 내용 해시 검사 없음

에이전트 초안도 읽을 수 있는 완성형 문서 형태 유지. 빈 제목, 임시 문구, 근거 없는 설계 의도 금지.

### 위키 커밋과 push

개발자의 편집 완료 전달 또는 명시적 push 요청 이후 에이전트 책임:

1. 현재 `docs/wiki/` 변경 파일 확인
2. 사용자 작업과 무관한 변경 제외
3. `문서 수정: <작업 요약> 위키 갱신` 형식의 별도 커밋 생성
4. 관련 코드 커밋과 위키 커밋을 같은 push에 포함
5. PR 설명의 작업 세부사항에 위키 커밋 링크와 해당 커밋 SHA에 고정된 각 변경 문서의 GitHub blob 링크 추가

사람 편집 완료 전 자동 커밋·push 없음. 위키 변경 불필요 작업은 별도 위키 커밋 없이 근거만 PR에 기록.

완료 시 TODO의 위키 검토 결과와 문서 링크를 PR 설명으로 이동하고 TODO 삭제.

## 원격 push 전 확인

```powershell
./Scripts/Agent/Ensure-AgentDependencies.ps1 -HostName codex
```

추가 확인:

1. 코드와 에이전트 위키 초안의 일치 여부
2. Obsidian 편집 완료 전달 또는 위키 변경 불필요 근거
3. 위키 변경 시 별도 `문서 수정` 커밋
4. PR 작업 세부사항의 위키 커밋·커밋 SHA 고정 문서 링크
5. 관련 빌드·테스트 결과
6. `graphify-out/`과 `.agent-tools/`의 Git 미포함 상태

Graphify 생성물 최신성 stamp·export·guard 요구 없음.

## 재현성 경계

동일 소스·버전·ignore 규칙의 code-only AST corpus: 높은 재현성.

공유 정본: 원본 코드, `docs/wiki/`, ignore 규칙, 의존성 버전. 로컬 Graphify 출력: 탐색 가속용 캐시.
