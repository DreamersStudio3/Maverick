# 실험동 B — 승강 보스 스테이지

- 레벨: `/Game/LevelDesign/Blockout/Maps/Experiment/L_BO_Experiment_ElevatorTower`, 기존 A 레벨과 분리
- 에셋: `/Game/LevelDesign/Blockout/Ingredients/ExperimentTower/`
- 책임: `BP_ExperimentElevator`가 전투·다리·승강 상태 관리, `BP_ExperimentCheckpoint`가 상호작용 전달
- 체크포인트: E 키 → 전투 시작 / 다음 층 / 돌아가기

## 치수

| 항목 | 값 |
| --- | --- |
| 건물 | 14개 층, 층 간격 8m |
| 중앙 공간 지름 | 최하단 40m → 최상단 32m, 높이에 따라 선형 축소 |
| 스테이지 | 초기 지름 30m, 난간 없음 |
| 스테이지 축소 | 중앙 공간과 동일 비율, 최종 정차점 약 24.46m |
| 회랑 깊이 | 6m |
| 다리 | 4방향, 폭 3.2m, 초기 길이 7m. 양 끝 1m 중첩 |
| 방 | 8×10m / 12×16m / 18×18m / 24×20m |
| 방 배치 | 7개 정차 높이마다 4개, 총 28개 |
| 출입구 | 폭 3.2m, 높이 4m, 문짝 없는 개구부 |

방 크기는 블록아웃 외곽 기준이며 벽 두께만큼 유효 폭 감소. 회랑 난간은 유지하되 다리 연결점은 개방.

## 이동과 전투

- 시작 높이를 0으로 계산: 정차 높이 0 / 16 / 32 / 48 / 64 / 80 / 96m
- 한 번에 2개 층, 총 6회 상승으로 12개 층 높이 이동
- 물리적 최상단 바닥은 104m. 최종 정차점 위의 한 층은 건축적 여유 공간
- `StageIndex`는 이동 횟수 0~6. 최종값 6에서는 추가 이동과 전투 시작 차단
- 중앙 공간 비율: `1 - LiftHeight / 52000`, Unreal cm 단위

| 입력 / 상태 | 동작 |
| --- | --- |
| 전투 시작 | 다리 2초 수납 → 현재 높이에서 전투, 상승 없음 |
| 전투 완료 | 체크포인트 복구 및 완료 메뉴 표시 |
| 대기 상태에서 다음 층 | 다리 2초 수납 → 4.5초 동안 16m 상승 → 다리 2초 전개 |
| 전투 완료 후 다음 층 | 수납된 상태에서 4.5초 상승 → 다리 2초 전개 |
| 최종 도착 | 추가 상승 버튼 비활성화 |

승강 시간 4.5초는 수납·전개 시간을 제외한 실제 이동 시간. 상승에 맞춰 스테이지·지지부와 다리 길이·위치를 조정하며 체크포인트 크기는 유지.

### 승강 회전

- 매 이동마다 높이 +16m, Yaw +90도. 수납 완료 후 4.5초간 동시에 변화
- 보간 진행률 `t = min(PhaseTime / 4.5, 1)`, 가감속 곡선 `t³(6t²-15t+10)`를 높이와 회전에 공통 적용
- `StartYaw`에 출발 각도 저장, `LiftYaw`를 누적하여 6회 이동 후 540도 도달
- 스테이지와 부속물이 함께 회전. 다리의 방사 위치와 자체 Yaw에도 누적 회전 적용
- 회전·상승 완료 후 다리 전개. 90도 간격의 회랑 출입구와 정렬 유지
- 캐릭터는 CharacterMovement의 이동 바닥 회전 추종 사용(`bIgnoreBaseRotation=false`). 엔진이 바닥 회전량을 ControlRotation에 더하므로 기존 시점 입력 유지
- 전투 중에는 승강과 회전 모두 정지

## 다리와 승강 카메라

- 동·북·서·남 다리 Yaw: 0 / 90 / 180 / -90도. 길이축을 각 방사 방향과 일치
- 높이 비율 `s = 1 - LiftHeight / 52000`: 다리 길이 `500s + 200cm`, 전개 중심 반경 `1750s cm`
- 수납 거리 `500s + 180cm`. 외측 끝을 스테이지 반경보다 80cm 안쪽으로 넣고, 상면도 20cm 내려 바닥 내부에 수납
- 기존 남북 다리 오류: 네 다리 Yaw가 모두 0도로 저장되어 길이 대신 폭이 빈 공간을 연결
- `PrepareTravelCamera`: 현재 SpringArm 위치 지연 설정 저장 후 비활성화. 캐릭터 이동 컴포넌트가 승강 액터 갱신 후 처리되도록 Tick 선행 관계 설정
- `RestoreTravelCamera`: 다리 전개 완료 후 원래 위치 지연 설정 복구. 다른 레벨의 기본 카메라 설정은 수정하지 않음
- 승강 카메라 진단: 수정 전 캐릭터 대비 카메라 Z 차이 49.696 → -34.749cm, 약 84.45cm 지연. 수정 후 상승 중 49.696cm 유지

## 검증

- Blueprint 컴파일 및 레벨·위젯 저장 완료
- 28개 출입구의 중앙과 좌우 1m 지점: 84회 수평 충돌 검사 통과
- 28개 방 바닥: 바닥 높이 일치 확인
- PIE: `NextLevel` 이벤트 6회 실행, 높이 1600cm 간격 증가 및 최종 9600cm 확인
- PIE: 각 정차점에서 다리 전개 완료, 7번째 이동 요청 차단
- PIE: 최종 스테이지 지름 24.4615m, 플레이어가 스테이지를 따라 상승한 위치 확인
- 다리 수정 후 PIE 6회 상승 재검증: 네 방향 회전·길이·정차 위치 일치, 수납 시 스테이지 내부 포함, 도착 시 카메라 지연 복구
- 카메라 비교용 `TowerLiftTrace` / `TowerLiftFixedTrace` 임시 로그는 검증 후 그래프에서 제거
- 카메라 수정 후 2,160개 상승 프레임 로그: 높이 차이 최소·최대 모두 49.696cm
- 회전 추가 후 PIE 6회 상승: 누적 각도 90/180/270/360/450/540도 확인
- 플레이어 초기 반경 650cm 유지, 카메라 방향 동반 회전, 정차 후 네 다리 방위 정렬 확인
- 최종 높이 96m 및 추가 이동 차단 상태 유지. 중간 진행률과 위치로 상승·회전 가감속 확인
- 4.5초 및 5차 가감속 곡선 적용 후 PIE 재검증: 38개 상승 표본에서 계산 곡선과 높이 오차 0cm, 도착 높이 16m·각도 90도·다리 전개 완료 확인
- `DebugNextFloor`는 다음 층 버튼과 같은 `NextLevel` 이벤트 실행. 이번 반복 검증은 이 경로 사용
- 전투 중 고정 높이는 그래프 경로 확인. 이번 변경 후 전투 전체 및 마우스 버튼 클릭 재검증은 별도 플레이 확인 대상

## 프로토타입 범위

- `BP_ExperimentBoss`는 기존 Duelist 기반 테스트 보스. 서로 다른 보스 6종의 배치·순서 데이터는 미구현
- 방은 이동과 크기 비교용 빈 공간. 조사 콘텐츠·프랍 미배치
- `DebugNextFloor`, `DebugDefeatBoss`는 PIE 검증용 플래그, 기본값 false
- 전투 종료만으로는 다리가 열리지 않으며 다음 층 도착 후 개방. 승리 직후 같은 층 탐색 개방은 별도 흐름 조정 필요
