# TODO 작업 기록 규칙

`TODO/`는 에이전트와 작업자 사이에서 현재 작업의 실행 맥락을 짧게 공유하는 공간이다. 장기 위키나 완료 이력 저장소가 아니다.

## 작업 시작

- 새 작업을 받으면 충돌하지 않는 이름의 `TODO/<task>.md`를 만들거나 기존 작업 파일을 이어서 사용한다.
- 목표, 범위, 시작 상태, 결정 사항, 단계별 체크리스트, 검증 결과를 기록한다.
- 사용자의 원문 전체나 코드 조사 결과를 복제하지 않고 다음 작업자가 이어받는 데 필요한 정보만 남긴다.

## 작업 중

- 범위나 구현 판단이 바뀐 시점, 검증이 끝난 시점, 새 차단 요인이 생긴 시점에 갱신한다.
- 체크박스만 채우지 말고 중요한 판단의 이유와 확인한 근거 파일을 짧게 기록한다.
- 여러 에이전트가 병렬 작업할 때는 한 작업 파일을 조정 기준으로 삼고, 서로 다른 작업을 한 파일에 섞지 않는다.

## 작업 종료

- 모든 항목을 완료 처리하고 결과물, 검증 명령, 남은 후속 작업을 적는다.
- 장기 보존 가치가 있는 구조·설계·운영 지식은 `docs/wiki/`로 옮긴다. 테이블 파이프라인과 schema가 바뀌면 `MaverickDesign/README.md` 또는 `MaverickDesign/Schema/README.md`를 갱신한다.
- TODO 파일은 Graphify 입력에서 제외한다. 작업 로그와 미완성 가설이 지식 그래프를 오염시키지 않도록 하기 위함이다.
- 오래된 TODO 정리는 별도 범위로 수행한다. 다른 작업자의 기존 파일을 임의로 삭제하거나 재작성하지 않는다.
