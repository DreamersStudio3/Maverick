# 작업 기록 규칙

`docs/todo/`는 진행 중인 작업의 짧은 인수인계 메모만 둔다. 장기 설계나 완료 이력을 쌓는 폴더가 아니다.

1. 작업을 시작할 때 `docs/todo/<task>.md` 하나를 만들고 목표, 현재 상태, 중요한 결정, 위키 검토, 검증 결과만 적는다.
2. 범위나 판단이 바뀌거나 검증이 끝났을 때만 갱신한다. 프롬프트 원문, 긴 코드 조사, 일반적인 Git 절차는 복제하지 않는다.
3. 구현과 검증이 끝나면 에이전트가 실제 변경 근거를 바탕으로 `docs/wiki/` 초안을 생성·갱신한다. 위키 변경이 필요 없으면 그 이유를 `위키 검토` 항목에 기록한다.
4. 개발자가 Obsidian 편집 완료를 알리면 에이전트가 별도 승인·초안 비교 없이 현재 위키를 전용 커밋으로 기록한다.
5. PR을 만들 때 위키 커밋과 해당 커밋에서 변경한 문서 링크 또는 변경 불필요 사유를 작업 세부사항으로 옮긴다.
6. 완료 파일은 삭제한다. 나중에 이력을 찾는 데 실제 도움이 되는 결과만 [Completed-Work.md](Completed-Work.md)에 한두 문장으로 합친다.

작업 파일의 최소 형식은 다음과 같다.

```markdown
# 작업명

- 목표:
- 상태:
- 결정:
- 위키 검토: `갱신: docs/wiki/<문서>.md` 또는 `변경 불필요: <이유>`
- 검증:
```

이 폴더는 미완성 가설의 위키 혼입 방지를 위해 Graphify 입력에서 제외한다.
