# 포식자의 순환 — 설계와 구현 단계

- 기록일: 2026-10-04
- 대상: 채찍·에너지소드 무기 패시브
- 기획 효과: 스킬로 적 타격 시 10% 확률로 소모한 마나와 쿨타임 환원
- 진행 순서: 5 / 5; 이전 [피 흘린 만큼..](blood-price.md)
- 진행 상태와 실제 검증 기록: [순차 구현 작업 메모](../../todo/weapon-passive-sequence.md)
- 승인 범위: 패시브별 문서 저장과 순차 구현 방식; 확률 판정 단위 등 세부 제안은 구현 단계에서 검토
- 협업 방식: 사용자가 코드·에셋 수정, 에이전트가 정확한 위치·변경 전·변경 후·확인 방법 안내

## 동작 설계

스킬 실행마다 실제 지불한 마나와 실행 출처를 보관
유효한 스킬 명중에서 확률을 판정하고, 성공하면 해당 실행의 마나와 주 쿨타임을 한 번 환원

1. 스킬 실행 시작 시 실행 번호·스킬 식별 정보·무기 출처 기록
2. 비용 지불 성공 시 실제 마나 감소량 기록
3. 대상 스킬의 유효 명중인지 확인한 뒤 10% 판정
4. 성공 여부를 먼저 기록해 재진입·중복 환원 차단
5. 기록한 마나를 회복하고 전투 컴포넌트에 해당 실행의 주 쿨타임 환원 요청
6. 행동 종료 시에도 환원 결과를 보존한 뒤 실행 기록 정리

| 항목 | 기준 | 구분 |
|---|---|---|
| 발동 확률 | 10% | 기획 |
| 판정 단위 | 성공 전까지 유효 스킬 타격마다 판정 | 제안 |
| 환원 횟수 | 같은 스킬 실행에서 최대 한 번 성공 | 제안 |
| 마나 | 해당 실행에서 실제 지불한 마나 전액 | 제안 |
| 쿨타임 | 명중을 발생시킨 스킬의 주 쿨타임 전액 | 제안 |
| 제외 | 평타, 별도 직접 피해·지속 피해, 체력·스태미너 비용, R 게이지 | 설계 |
| 무기 변경·사망 | 이전 실행 기록과 미처리 요청 무효화 | 설계 |

타격마다 판정하면 5타 스킬의 한 번 이상 발동 확률은 `1 - 0.9^5 ≈ 40.95%`
사용당 확률을 10%로 고정하려면 첫 유효 명중에서 한 번만 판정하는 방식으로 확정 필요

## 실제 소비량과 실행 식별

- `AbilityData.MpCost`의 현재 값만 다시 읽지 않고 실제 비용 지불 결과 보관
- 비용을 내지 못해 실행되지 않은 스킬은 환원 대상이 아님
- 한 실행의 여러 Notify 구간에서 비용이나 환원을 중복 기록하지 않음
- `AttackInstanceId`와 소속 스킬을 연결하고, 연계 스킬은 해당 연계 실행도 함께 식별
- 체인 단계가 진행돼도 현재 단계 조회값으로 이전 명중의 스킬을 잘못 찾지 않도록 보관한 출처 사용
- 마나 환원은 기존 `RecoverMP` 경로로 최대치까지 회복; 기존 명중당 마나 회복과 구분해 시험
- 실제 소비 마나가 0이면 마나 환원은 0, 쿨타임 환원 가능 여부는 별도로 판단

## 쿨타임 환원과 연계 스킬

이전 피 흘린 만큼..에서 만든 전투 영역의 공통 쿨타임 처리 사용
확률 성공 여부와 실행별 환원 요청을 보관해 행동 종료 처리의 시간 재설정에도 결과 유지

| 상태 | 환원 처리안 |
|---|---|
| 해당 실행의 주 쿨타임이 이미 진행 중 | 남은 시간을 0으로 설정 |
| 명중 순간에는 주 쿨타임이 아직 시작되지 않음 | 해당 실행의 쿨타임 시작 처리에서 면제 |
| 같은 연계 스킬을 진행 중 | 연계 단계·입력 제한·단계 사이 대기시간 유지, 해당 연계의 주 쿨타임 면제 |
| 다른 스킬의 쿨타임 | 유지 |
| 다음 신규 스킬 사용 | 이전 환원 성공 기록을 넘기지 않음 |

- 각 연계 단계는 실제 비용을 지불한 실행분의 마나만 환원
- 주 쿨타임 면제는 해당 연계에만 귀속; 같은 연계에서 추가 성공해도 이후 새 사용으로 혜택을 넘기지 않음
- `StartPostAbilityResetWindow`와 연계 완료 처리에서 환원이 덮어써지는지 확인
- 쿨타임 UI와 실행 가능 검사는 같은 값을 사용
- 쿨타임이 환원돼도 현재 액션·입력 제한이나 R 게이지 조건을 강제로 해제하지 않음
- 적이 여러 명이거나 타격이 여러 번이어도 같은 실행의 마나가 두 번 돌아오지 않도록 실행 번호로 차단

## 자산과 생명주기

- `DA_Passive_PredatorCycle`, `UMVPredatorCyclePassiveBehavior` — 가칭
- 본체 `Infinite`·`NoStack`·`OnePerSource`, 별도 중첩 상태 효과 불필요
- 유연한 흐름과 같은 채찍·에너지소드 세트에 본체 등록
- 본체는 명중 구독과 확률 판정 담당; 비용 기록과 실제 환원은 Ability·전투·스탯 영역의 책임으로 분리
- 사건 구독 제거와 실행 기록 정리를 통해 사망·장착 변경 뒤 지연 명중의 환원 방지
- 이미 돌려준 마나를 장착 해제 시 회수하지 않음; 무효화 대상은 미처리 요청과 실행 기록
- 신규 GameplayTag는 프로젝트의 `MVGameplayTags.h`·`.cpp`에서 선언·정의

## 구현 단계

| 단계 | 작업 | 확인 기준 |
|---:|---|---|
| 1 | 판정 단위 확정, 실행별 실제 마나 소비량과 출처 기록 | 비용 지불 성공 시 한 번 기록, 다음 실행에서 분리 |
| 2 | 본체·세트와 명중 연결, 시험 확률 100%로 마나 환원 | 실제 소비분만 최대치까지 한 번 회복 |
| 3 | 진행 중·시작 전·연계 주 쿨타임 환원 연결 | 행동 종료 후에도 환원 유지, 다음 신규 사용은 정상 쿨타임 |
| 4 | 0%·100% 경계와 10% 판정, 다단·다수 대상·무기 변경 시험 | 중복 환원·출처 혼동 없음 |
| 5 | 시험 확률·임시 로그 정리, 사용자 실행 확인 | 최종 확률 10%, 정상 동작과 보류 범위 기록 |

## 완료 기준

- 소비량 0·양수, 최대 마나 근처, 기존 명중당 회복과 동시 적용 확인
- 다단·광역 공격에서 같은 실행의 환원은 최대 한 번
- 확률 0%에서는 발동 없음, 100%에서는 조건을 만족할 때 발동; 짧은 실행의 빈도로 10% 정확성을 단정하지 않음
- 단발·연계 스킬 모두 종료 뒤 쿨타임이 다시 생기지 않는지 확인
- 타 스킬·연계 입력 시간·R 게이지 유지, 새 사용으로 이전 환원이 넘어가지 않음
- 사망·무기 교체·장착 해제 뒤 이전 실행에서 환원하지 않음
- 임시 로그 접두어 제안: `PredatorCycleTrace`; 실행 번호·스킬·실제 비용·판정값·환원 여부·쿨타임 전후 기록
- 완료 뒤 실제 동작을 무기 패시브 위키에 반영하고 요청한 5종의 완료·보류 상태 정리
- 다른 패시브를 임의로 추가 진행하지 않음
