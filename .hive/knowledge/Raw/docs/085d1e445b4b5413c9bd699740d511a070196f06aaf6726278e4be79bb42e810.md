# Graphify 도입 보고서

## 현재 결론

Graphify 역할: 에이전트의 코드 탐색 범위 축소를 위한 로컬 query-driven 캐시.

공유 정본:

- 원본 코드와 설정
- `docs/wiki/` 사람용 위키
- `.graphifyignore`
- `Config/AgentDependencies.json`
- `AGENTS.md`, `POLICY.md`, 실행 wrapper

로컬 전용:

- `.agent-tools/graphify/`
- `graphify-out/` 전체
- Graphify query 로그와 cache

## 2026-08-10 운영 전환

변경 배경:

- 커밋마다 로컬 graph 변경 발생
- 생성 wiki와 `graph.json`의 높은 파일 churn
- 브랜치 간 대규모 생성물 diff와 저장소 크기 증가
- 동일 코드 AST의 로컬 재생성 가능성
- 사람이 관리하는 `docs/wiki/` 정본의 별도 존재

변경 결과:

- commit-driven 갱신에서 query-driven 갱신으로 전환
- post-commit·post-checkout Graphify 훅 제거
- 생성물 전제 pre-push guard와 wrap-up 절차 제거
- `graphify-out/` Git 추적 종료와 전체 ignore
- Graphify `0.9.38` 프로젝트 고정
- 질의 wrapper에서 초기 code-only 추출 또는 AST 증분 갱신
- 첫 material 작업과 push 전 Hive·Graphify 의존성 자동 준비

## 재현성 판단

동일 조건의 입력 corpus:

- 동일 Git snapshot
- 동일 `.gitignore`, `.graphifyignore`
- 동일 Graphify 버전과 실행 옵션
- 동일한 로컬 추가 파일 부재

code-only AST graph: tree-sitter 기반 로컬 추출, 높은 재현성 기대.

전체 의미 graph와 생성 wiki: byte 단위 동일성 보장 대상 제외. 차이 원인:

- LLM 기반 문서 의미 추출
- backend·model·버전 차이
- 커뮤니티 분할과 이름 생성 차이
- 생성 시각과 도구 schema 변화

Maverick 기본 경로: code-only AST graph + 원본 `docs/wiki/` 직접 확인.

## Agent 사용 흐름

개발자 입력: 평소 코드베이스 질문.

에이전트 내부 절차:

1. `AGENTS.md`와 Graphify skill 기준 확인
2. 프로젝트 의존성 자동 준비
3. 구조·관계 질문 여부 판단
4. query wrapper 실행
5. 로컬 graph 초기화 또는 증분 갱신
6. scoped subgraph 조회
7. 관련 원본 코드와 Unreal asset 검증

개발자의 직접 `graphify query` 입력 요구 없음.
