# 아이템 습득 알림

플레이어가 철 파편 3개를 받으면 하단 중앙에 카드 세 장이 겹쳐 뜨고, 오른쪽에는 철 파편 이름과 아이콘이 세 줄 뜬다. 적이 떨어뜨린 물건을 줍거나 보상으로 바로 받을 때 같은 규칙을 적용한다. 같은 아이템을 다시 얻어도 두 곳에 모두 표시한다

## 원본에서 가져올 화면

| 위치 | FrameworkTest 원본 | Maverick에서 보여 줄 내용 |
|---|---|---|
| 하단 중앙 | `/Game/SoulslikeFramework/Widgets/HUD/W_FirstLootNotification` | 카드 한 장에 아이템 이름과 큰 그림, 최초 습득 시 `NEW`, 재습득 시 `획득` 표시. 연속 습득 시 최대 세 장을 세로로 조금씩 어긋나게 겹침 |
| 오른쪽 | `/Game/SoulslikeFramework/Widgets/HUD/W_LootNotification` | 아이템 한 개당 작은 그림과 그 왼쪽에 우측 정렬한 이름 표시 |

원본 두 위젯에서 배치, 장식, 서체와 페이드 애니메이션을 가져온다. 원본 HUD의 오른쪽 목록 자리는 `ItemLootNotificationsBox`. 에디터에서 부모 슬롯의 위치·간격과 애니메이션 대상을 함께 확인한다. 원본의 견본 아이콘과 `BFL_Helper` 호출은 Maverick의 표시 데이터로 교체한다

이식 위치는 `/Game/UI/Notifications/ItemAcquisition/`으로 제안한다. 상호작용 안내에 사용한 `MI_FadingBorder_Double_Med`, Liberation Serif와 한글 대체 글꼴 처리를 재사용한다. 원본의 `MI_FadingBorder_Double_New`, `MI_FadingBorder_L_Softest` 등 필요한 장식은 기존 자산과 대조해 옮긴다

## 지급과 알림의 연결

`지급 요청 → 인벤토리에서 지급 확정 → OnItemAcquired 한 번 → 로컬 플레이어 UI → 수량만큼 하단 카드와 오른쪽 목록 표시`

1. **지급하는 곳**은 기존 인벤토리 API로 아이템 태그와 수량을 전달한다. 적이 구체를 생성한 시점과 플레이어가 구체를 주운 시점을 구분한다. 향후 상점 구매, 제작 결과, 대화·퀘스트 보상도 지급이 성립한 시점에 같은 API를 사용한다
2. **인벤토리**는 성공한 지급당 `OnItemAcquired`를 한 번 보낸다. 전달값 `FMVItemAcquisition`은 `ItemTag`, 실제 지급량 `GrantedQuantity`, 슬롯 기준 최초 여부 `bFirstAcquisition`이다. 수량을 지급 시점에 확정하므로 알림이 뜨기 전에 아이템을 사용해도 받은 개수만큼 표시한다
3. **UI**는 소유 플레이어의 사건 한 건을 받아 `FindInventoryItemDefinition(ItemTag)`로 공통 아이템 행의 `DisplayName`과 `Icon`을 한 번 읽어 두 대기열에 추가한다. 이름이 비었으면 인벤토리처럼 태그 이름을 쓰고, 아이콘이 비었거나 읽기에 실패하면 공통 가방 그림을 쓴다. 늦게 도착한 아이콘은 해당 알림에만 반영한다

신규 아이템은 기존에 등록된 표에 유효한 행을 추가하면 두 알림의 대상이 된다. 현재 색인은 플레이어 무기·소모품·재료 표를 읽는다. 장비처럼 새 종류의 표를 도입할 때는 공통 아이템 행과 인벤토리 색인·지급 규칙을 연결한다. 두 위젯은 공통 표시 데이터만 받아 아이템 종류가 늘어도 같은 방식으로 그린다. [아이템 공통 행](../../Source/Maverick/Public/Tables/MVItemTableTypes.h) · [아이템 색인](../../Source/Maverick/Private/Tables/MVInventoryItemIndex.cpp)

### 기존 지급 경로별 처리

| 현재 경로 | 알림을 결정하는 시점 |
|---|---|
| 적 드랍 줍기, 블루프린트의 `TryAddItem`, 개발 명령 `MV.Inventory.Grant` | 공통 `TryGrantItem`에서 실제 지급량 확정 후 1회. 바깥 호출은 결과만 받음 |
| 고정 배치물 `TryGrantPlacedPickup` | 수량과 필드의 습득 기록을 함께 반영한 뒤 1회. 거절·수량 되돌리기에는 0회 |
| 기존 무기 지급 `AcquireWeapon` | 플레이어 지급은 기존 무기 행 검사를 거쳐 같은 성공 처리로 연결. 기본 무기 구성과 NPC 무기 부여는 조용히 처리 |
| 초기 소지품, 저장 불러오기, 휴식·부활 포션 보충, 사용·소비·제거 | 상태 복원 또는 수량 조정. 가방·HUD 갱신만 수행 |
| 보유 한도 초과, 이미 가진 단일 소유 무기, 잘못된 태그·수량 | 실제 지급 0개. 성공 알림 0건, 기존 실패 안내 처리 |

`OnInventoryChanged`는 기존 가방·장착 화면 갱신에 사용한다. 낮은 단계의 수량 변경이나 복원 방송을 구독해 습득을 추측하면 포션 보충과 실제 보상을 구분할 수 없다. 기존 블루프린트 호출도 점검해 게임플레이 지급에는 지급 API, 절대 수량 설정에는 복원 API를 사용한다. [인벤토리 지급](../../Source/Maverick/Components/MVInventoryComponent.cpp) · [무기 지급](../../Source/Maverick/Components/MVWeaponComponent.cpp) · [포션 보충](../../Source/Maverick/Character/PC/Consumable/MVPlayerConsumable.cpp)

고정 배치물의 성공 기준은 현재 게임 세션에서 지급이 확정되었는지다. 현행 `TryCommitPlacedPickup`은 디스크 저장을 시도하고, 쓰기 실패를 별도 상태로 남긴다. 쓰기 재시도는 같은 습득 알림을 다시 만들지 않는다. [필드 습득 기록](../../Source/Maverick/System/MVWorldStateSubsystem.cpp)

## 최초 습득과 기존 저장 호환

- 저장 슬롯별로 `FMVInventorySaveData`에 발견한 아이템 태그 집합을 보관한다. 시작 소지품은 이미 아는 아이템으로 등록한다. 처음 받는 태그만 `NEW`이고, 전부 사용하거나 버렸다가 다시 받아도 `획득`으로 표시한다
- 일반 지급은 수량과 발견 기록을 함께 준비한 뒤 기존 저장·변경 통지를 호출한다. 고정 배치물도 같은 두 값을 저장 자료에 담고, 지급이 거절되면 임시 변경을 모두 되돌린다. 일반 저장과 고정 배치 저장 모두 인벤토리의 같은 저장 자료 생성 함수를 사용해 발견 기록이 덮어써지는 일을 막는다. [일반 저장](../../Source/Maverick/Components/MVWeaponProgressSave.cpp) · [저장 구조](../../Source/Maverick/System/MVWorldStateTypes.h)
- 발견 기록이 없는 기존 슬롯은 복원된 소지품 태그를 이미 발견한 것으로 시작한다. 예전 버전에서 얻고 모두 소비한 아이템은 옛 저장 자료만으로 이력을 알 수 없어, 업데이트 후 다시 받을 때 한 번 `NEW`가 뜰 수 있다

## 연속 습득과 화면 배치

아이템 한 개당 하단 카드 한 장과 오른쪽 목록 한 줄을 표시한다. 여러 묶음을 받으면 먼저 지급한 묶음의 알림부터 표시한다. 대기열은 이름·아이콘과 남은 수량을 묶음 단위로 보관하고, 화면에 자리가 생길 때 한 개씩 표시한다. 처음 발견한 묶음의 첫 카드만 `NEW`를 띄운다

### 하단 카드 세 장의 배치와 교대

1. 가장 먼저 받은 카드를 하단 중앙의 기준 위치에 맨 앞으로 그린다. 두 번째와 세 번째 카드는 같은 가로 중심에 놓고 뒤로 한 장 갈 때마다 조금씩 위로 올린다. 세로 간격은 화면 배율에 따라 조정하며, 앞장에 적힌 이름과 그림이 온전히 보이고 뒷장의 윗단이 드러나게 한다
2. 세 장까지는 함께 표시하고 네 번째부터는 습득 순서대로 대기시킨다. 화면에 자리가 나기 전에는 대기 항목의 데이터만 보관한다. 각 카드는 맨 앞에 완전히 자리 잡았을 때부터 읽을 시간을 갖는다. 시험 시작값은 2초이며, 배경에서 기다린 시간도 앞장의 퇴장 애니메이션 시간도 여기에 포함하지 않는다
3. 맨 앞 카드의 페이드가 끝나면 그 카드를 제거한다. 같은 갱신에서 둘째 카드를 맨 앞으로, 셋째 카드를 둘째 자리로 옮기고, 가장 오래 기다린 항목을 맨 뒤에 표시한다. 이동 중 새 습득이 들어와도 같은 대기열 끝에 추가한다. 퇴장 중인 카드까지 포함해 화면에는 항상 최대 세 장만 보인다

**다섯 건을 A부터 E까지 동시에 받았을 때**

| 시점 | 맨 앞 | 둘째 | 맨 뒤 | 표시 대기 |
|---|---|---|---|---|
| 지급 직후 | A | B | C | D, E |
| A 퇴장 직후 | B | C | D | E |
| B 퇴장 직후 | C | D | E | 없음 |
| C 퇴장 직후 | D | E | — | 없음 |
| D 퇴장 직후 | E | — | — | 없음 |
| E 퇴장 직후 | — | — | — | 없음 |

### 오른쪽 목록과 화면 입력

- 오른쪽은 최대 세 줄을 동시에 표시한다. 각 줄은 처음 보인 순간부터 시험 시작값 3초 동안 표시하고, 빈자리에는 다음 대기 항목을 넣는다. 하단 카드와 오른쪽 목록은 같은 습득 순서를 받아 각자의 속도로 소화한다
- 두 알림은 키 입력과 마우스 포커스를 받지 않는다. 하단 맨 앞 카드의 아래쪽과 E 상호작용 안내 사이에 간격을 두고, 뒷장은 위로 쌓아 다음 아이템을 계속 주울 수 있게 한다
- 표시 담당은 `UMVUISubsystem`에서 소유 플레이어의 인벤토리에 한 번 연결한다. 기본 화면의 `WidgetLayer`에 투명한 알림 컨테이너 하나를 두고 두 위치와 표시 순서를 관리한다. 현재 일반 팝업을 여는 `PushPopupByClass`는 기존 팝업을 닫으므로 습득 카드가 E 안내나 대화창을 닫지 않도록 이 경로를 쓰지 않는다. [화면 계층](../../Source/Maverick/UI/System/MVUILayerBase.cpp) · [UI 관리](../../Source/Maverick/UI/System/MVUISubsystem.cpp)
- 로컬 플레이어의 인벤토리가 정해지면 첫 게임플레이 지급 전에 연결한다. 화면 생성이 늦으면 같은 세션의 지급을 보관했다가 표시한다. 메뉴에서 구매·보상을 받아도 해당 화면 위에 두 알림을 표시한다. 캐릭터 교체 시 구독을 옮기고, 같은 슬롯의 화면 재생성에서는 미표시 건을 이어간다. 다른 슬롯·새 게임으로 넘어가면 이전 대기열과 타이머를 정리한다

## 단계별 구현과 완료 기준

| 단계 | 구현 | 완료 기준 |
|---|---|---|
| 1. 화면 이식 | 두 원본 위젯과 장식·페이드를 이전하고 하단 한 장·두 장·세 장 배치를 샘플로 구동 | 한글 이름과 아이콘 표시. 원본 프로젝트 연결 없이 로드. 화면 비율을 바꿔도 뒷장 윗단이 구분되고 맨 앞 카드와 E 안내를 모두 읽을 수 있음 |
| 2. 지급 확정과 최초 기록 | 일반 지급·고정 배치·기존 플레이어 무기 지급을 연결하고 저장 호환 적용 | 지급 1회당 사건 1건. 실패·복원·보충은 0건. 전량 사용 후 재획득과 재실행에서도 최초 표시가 반복되지 않음 |
| 3. 실제 UI 연결 | 로컬 인벤토리 구독, 하단 세 장과 대기열, 오른쪽 목록, 입력 통과, 화면 재연결 처리 | 철 파편 3개를 한 번에 지급하면 하단 세 장과 오른쪽 세 줄 표시. 오른쪽 이름은 아이콘 왼쪽에서 우측 정렬. 연속 지급이나 퇴장 중 추가에도 아이템별 표시 순서·세 장 상한 유지. 각 카드는 맨 앞에서 온전한 표시 시간 확보. 메뉴·다음 E 입력 정상 |
| 4. TestMap 통합 검증 | 별도 시험 슬롯에서 고정 포션·철 파편·쌍검, 적 드랍, 직접 지급, 기존 슬롯 호환을 시험 | 바닥 줍기와 직접 지급에서 동일한 두 알림 확인. 누락 아이콘은 대체 그림 표시. 중복 무기·한도 초과·이미 소비된 배치물·재접속에서 거짓 알림 0건. 별도 슬롯 간 기록·대기열 분리 |
