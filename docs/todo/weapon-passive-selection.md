# 무기 패시브 단일 선택 전환

- 목표: 무기별 패시브 후보 중 한 개만 선택·적용하는 구조와 기존 코드 이전·삭제 범위를 설계 문서로 기록한다.
- 상태: 1~4·6단계 구현과 7단계 위키 갱신 완료. 사용자 Windows Editor 빌드·재저장과 검↔맨손 PIE 성공. 5·7단계의 최종 무기 종류별·실제 패시브 지연 적중 경계는 미검증. 패시브 선택 UI는 별도 후속 작업
- 결정: 공용 Ability에 기존 상태 효과 한 개를 설정하고 기존 `Test_*` 스킬 트리에 스킬 행 등록. 카타나·레이피어, 석궁·활, 채찍·에너지소드는 후보를 재사용해도 종류별 선택은 각각 보관. 기존 `WeaponPassiveSet` 후보집 전환안 폐기
- 위키 검토: 갱신: `docs/wiki/Features/Combat/Weapon-Passives/document.md`. 구형 세트 적용 설명을 단일 선택 구조로 바꾸고 개별 패시브의 기존 구현 기록 유지
- 검증: 사용자 Windows Editor에서 공용 Ability·9종 Blueprint·패시브 표 저장, 최종 C++ 빌드와 `BP_ThirdPersonCharacter` 재저장 성공 보고. `FlexibleFlow` 선택 `true`와 본체 효과 수 0→1, O 해제·맨손에서 `None/0`, 검 재장착 직후 `FlexibleFlow/1`을 PIE에서 확인. 구형 컴포넌트·세트 참조 확인과 자산 삭제도 오류 없이 완료했다고 보고. `Maverick.Combat.Projectile.ExecutionLifetime` 시험은 오래된 탄의 기본 피해·원래 스킬 쿨타임 환원과 사망 보상 차단을 확인하지만 실제 패시브의 MP·화면 쿨타임 또는 패시브 교체 후 적중 효과는 증명하지 않음. 같은 스타일 다른 아이템·최종 무기 종류도 미검증. Agent 빌드·Editor 실행은 사용자 요청에 따라 미실행

## 5단계 작업 순서

1. 장착 아이템·종류·스타일 변화 시 기존 패시브를 정리하고 현재 종류의 선택을 다시 적용. 동일 아이템 재통지는 유지
2. 패시브 적용 세대와 공격 시작 시 세대를 기록. 모든 패시브 행동이 명중·빗나감·피해 보정 전에 같은 세대인지 확인
3. 같은 선택 재시도와 적용 실패 반환값을 바로잡고 임시 `WeaponPassiveTrace` 제거
4. 코드 정적 점검 뒤 사용자 빌드·실행 결과 확인. 빌드는 사용자 담당

## 6단계 작업 순서

1. Editor에서 확인한 `OneHand_TestSword.PassiveSet`을 `None`으로 바꾸고 저장. 다른 두 시험 행은 유지
2. 무기 상태의 구형 세트 복사와 캐릭터 기본 `WeaponPassiveComponent` 생성을 중지. 사용자 빌드 후 `BP_ThirdPersonCharacter`를 재컴파일·저장
3. 아홉 `BP_Passive_*`의 본체 직접 참조와 다섯 `DA_*_PassiveSet`의 외부 참조를 Editor에서 확인한 뒤 구형 세트 자산 제거
4. 자산 이전 완료 후 `PassiveSet` 필드·구형 컴포넌트와 세트 클래스 파일 제거
5. C++ 참조 검색과 정적 점검. 빌드·Editor 재저장·실행은 사용자 담당

## 7단계 작업 순서

1. 최종 C++ 삭제 뒤 사용자 빌드·Blueprint 재저장 결과 기록
2. 검 P 선택·O 해제와 검↔맨손 교체를 PIE에서 다시 확인
3. 현 시험 자산으로 실행 가능한 선택·해금 경계를 확인하고, 없는 무기·투사체 시나리오는 후속 검증으로 분리
4. 현재 코드 계약과 실제 확인 범위로 무기 패시브 위키 갱신
