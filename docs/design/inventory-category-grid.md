# 인벤토리 하위 분류와 고정 칸

Maverick · 구현 전 설계

## 화면 동작

보유 아이템은 같은 너비의 6칸을 왼쪽부터 채운다. 한 줄에 아이템이 2개면 첫 두 칸에 붙여 놓고, 오른쪽 4칸은 빈 칸으로 표시한다

같은 하위 분류의 아이템이 6개를 넘으면 다음 줄에 이어서 놓는다. 하위 분류가 바뀌면 이전 줄의 남은 칸을 비워 두고 다음 줄 첫 칸부터 시작한다. 전체 탭에서는 큰 분류가 바뀔 때도 같은 규칙 적용

```text
강화 소재 탭 예시 · 6열

[단석 1] [단석 2] [단석 3] [단석 4] [단석 5] [단석 6]
[단석 7] [ 빈 칸] [ 빈 칸] [ 빈 칸] [ 빈 칸] [ 빈 칸]
[은방울꽃 1] [은방울꽃 2] [ 빈 칸] [ 빈 칸] [ 빈 칸] [ 빈 칸]
```

빈 칸은 기존 인벤토리 스타일의 옅은 슬롯으로 표시한다. 아이템이 없는 하위 분류는 줄을 만들지 않고, 탭 전체가 비었을 때는 빈 격자 한 줄과 기존 빈 목록 안내를 보여 준다

## 분류와 데이터

큰 분류는 탭으로 고르고, 하위 분류는 탭 안에서 아이템을 줄 단위로 묶는다. 초기 탭 순서는 **전체 → 무기 → 소모품 → 소재 → 기타**

| 큰 분류 | 하위 분류 예시 | Maverick의 기존 데이터 |
|---|---|---|
| 무기 | 한손 무기, 쌍수 무기, 그 외 무기 | `DT_Weapons_Player`의 플레이어 무기 |
| 소모품 | 포션, 인챈트 아이템 | `DT_Items_Consumable`의 체력물약은 포션. 인챈트는 등록 후 해당 줄 표시 |
| 소재 | 일반 소재, 무기 강화 소재, 소환 강화 소재 | `DT_Items_Materials`의 철 조각은 일반 소재 |
| 기타 | 문서, 기록, 분류 미지정 | 해당 아이템을 등록하거나 기존 데이터에 분류를 지정할 때 표시 |

| 데이터 | 책임 |
|---|---|
| 아이템의 `ItemTag` | 보유, 수량, 선택과 저장에서 사용하는 기존 식별자 |
| 아이템의 `ItemType`과 행 구조체 | 포션 사용·보충, 무기 조회, 보유 상한 등 게임 규칙 |
| 아이템 행의 `InventoryGroupId` | 화면에서 어느 하위 분류에 배치할지 지정 |
| 아이템 행의 `InventorySortOrder` | 같은 하위 분류 안에서의 순서. 숫자가 작은 아이템부터 표시 |
| `DT_InventoryGroups`의 행 이름 | `InventoryGroupId`와 연결. 큰 분류, 하위 분류 표시 이름, 하위 분류 순서를 정의 |

- 아이템에는 하위 분류 하나를 지정. 예를 들어 `Consumables.Potion` 행에서 큰 분류를 `Consumables`, 표시 이름을 ‘포션’으로 정의
- 하위 분류 행은 데이터 표에서 추가 가능. 큰 분류 탭은 화면이 정의하고 ‘전체’는 모든 큰 분류를 보여 주는 탭으로 사용
- 현재 `UMVTableManager`는 무기·포션·소재 표별로 화면 분류와 보유 한도를 함께 정한다. 분류 도입 단계에서 포션 수량 변경·보충과 무기 조회는 각각의 원본 행 종류를 확인하도록 연결
- 현재 소모품 표의 행 구조체는 회복약 전용. 인챈트 아이템을 추가할 때는 해당 타입의 표를 아이템 색인에 등록하고 화면 분류만 `Consumables.Enchantment`로 지정
- 분류 값이 없는 기존 행은 원본 표에 맞는 기본 그룹으로 표시. 등록되지 않은 분류 키는 표의 행 이름을 포함해 기록하고 같은 기본 그룹으로 표시. 저장의 아이템 태그와 수량을 그대로 읽을 수 있으므로 저장 형식 변경 불필요

## 정렬과 고정 격자

1. 보유 아이템 중 선택된 탭에 해당하는 항목을 모음. ‘전체’에서는 모두 모음
2. 큰 분류 순서 → 하위 분류 순서 → 아이템 순서로 정렬. 같은 하위 분류 순서 값은 그룹 ID, 같은 아이템 순서 값은 `ItemTag`로 순서를 확정
3. 같은 하위 분류 안에서 왼쪽부터 최대 6개씩 배치. 분류의 마지막 줄은 남은 칸을 빈 슬롯으로 채우고 다음 분류는 새 줄에서 시작
4. 기존 인벤토리 목록의 스크롤 영역을 사용. 채운 칸과 빈 칸 모두 같은 열 폭과 행 높이를 사용하고, 폭이 달라지는 화면에서는 전체 격자에 같은 배율을 적용

현재 `UUniformGridPanel`은 실제로 채워진 열 수로 전체 너비를 나눈다. 6개 미만인 줄도 빈 슬롯을 포함해 항상 여섯 칸으로 구성하면 아이템 수가 바뀌어도 같은 화면 너비에서 열 간격이 유지된다

슬롯 크기는 기존 최소값인 **98×104 UI 단위**를 시작값으로 사용. 목록 아이콘은 현재 58×58에서 **72×72**로 키워 슬롯의 안쪽 여백과 오른쪽 아래 수량의 겹침을 확인한다

## 선택과 입력

- 빈 슬롯은 선택·마우스 클릭·키보드·패드 초점의 대상에서 제외
- 좌우는 같은 줄의 실제 아이템 사이에서 이동. 위아래는 인접한 줄에서 같은 열을 우선하고, 그 열이 비었으면 가장 가까운 실제 아이템으로 이동
- 수량이 바뀌거나 표를 다시 읽어도 같은 아이템 태그를 선택 상태로 유지. 화면에서 사라졌으면 현재 탭의 첫 아이템으로 이동하고, 탭이 비었으면 필터에 초점
- 키보드·패드로 화면 밖 아이템에 초점이 이동하면 목록을 스크롤. 선택한 아이템의 상세에는 기존 이름·수량·설명 표시

## 단계별 구현과 확인

| 단계 | 구현 | 통과 조건 |
|---|---|---|
| 1. 데이터 분류 | 분류표와 아이템 행 필드 추가. 기존 무기·포션·소재에 기본 그룹 지정. 무기·포션 처리에서 화면 분류 의존 분리 | 이전 저장의 소지품을 불러오고 무기는 1개, 포션은 기존 한도를 적용. 포션 소비와 휴식 보충, 무기 소유와 거점 퀵슬롯 검증 |
| 2. 고정 칸과 그룹 줄바꿈 | 기존 페이지에 고정 6열, 빈 칸, 하위 분류별 줄바꿈 적용 | 같은 분류 2개는 첫 줄에 나란히, 다른 분류 2개는 서로 다른 줄 첫 칸. 단석 7개 다음 은방울꽃 2개는 셋째 줄부터 표시 |
| 3. 조작과 화면 검증 | 탭·키보드·패드 초점·스크롤 연결, 슬롯과 아이콘 크기 확인 | 빈 칸 건너뛰기, 긴 목록 끝까지 이동, 수량 변경 뒤 선택 유지, 선택 항목 소진 시 초점 이동. 1280×720과 960×540에서 격자와 상세의 겹침 확인 |
